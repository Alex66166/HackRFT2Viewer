HackRF T2 Viewer 1.4.2-RC1 — диагностика

Статус: тестовая версия. Из имеющейся записи 586 МГц корректный TS пока
не получен. Успешный L1 сам по себе не означает приём телеканалов.

1. Запустите HackRFT2Viewer.exe. Выберите вашу частоту, 10 MS/s и полосу 8 МГц.
2. Запустите приём на 30–60 секунд. Во вкладке диагностики наблюдайте
   потери буферов, L1, BCH/BBFRAME и TS. Не меняйте сразу несколько настроек.
3. Нажмите сохранение диагностического отчёта. Рядом с выбранным TXT
   создаётся папка с суффиксом .files: runtime.log, fec-performance.log,
   stage-profile.csv и, если была ротация, предыдущие сегменты .1.
   Для анализа приложите TXT и архив этой папки.
4. Кнопка записи 3 секунд исходного I/Q сохраняет файл .cs8 и .cs8.json
   с форматом, частотой, частотой дискретизации, усилением и версией.
   На время этих 3 секунд оставьте параметры неизменными.
   Файл публикуется после полной записи; при остановке незавершённый захват
   не сохраняется как полноценный cs8. При 10 MS/s полный файл — 60 000 000 байт.
5. При открытии I/Q рядом лежащий JSON восстанавливает частоту и частоту
   дискретизации. Для старых файлов без JSON укажите их вручную до открытия.

Логи автоматически сохраняются отдельно для каждого запуска в локальных
данных приложения (полный путь указан в TXT-отчёте). Перезапуск не стирает
предыдущий сеанс. Каждый текстовый журнал ограничен двумя сегментами по 4 MiB,
CSV — двумя сегментами около 8 MiB. Сохраняются последние сеансы; старые
сверх девяти предыдущих удаляются при запуске, кроме сеансов текущего дня.
Никакой автоматической отправки диагностики нет.

Portable требует Windows x64 и процессор с AVX2. Необходимо установить
WinUSB-драйвер для HackRF через Zadig, если он ещё не установлен.
